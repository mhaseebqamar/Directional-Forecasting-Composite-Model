NVDA Multi-Horizon Directional Forecasting¶

Devvnex Quantitative Analyst Assessment — Submission¶
Asset NVIDIA Corporation (NVDA) — NASDAQ
Period January 2, 2024 – April 30, 2025
Model Pure-quantitative composite scoring engine with regime-gated signals
Output BUY / HOLD / SELL signals validated over 9 forward horizons (5 → 126 trading days)

Design summary¶

A weighted composite of four independent signal blocks — momentum, trend position, volume, and mean reversion — each normalized via rolling z-score and bounded by tanh. The composite is converted into discrete BUY / HOLD / SELL signals through four joint guardrails:

  1. Regime gate — SMA-50 (used only as a secondary filter, per the rules) must agree on direction
  2. Momentum confirmation — multi-block alignment required
  3. Extreme-stretch gate — don't chase tops, don't catch falling knives
  4. Pullback-within-trend — BUYs require a Donchian-position pullback, not fresh highs

A strict chronological 70/30 train/test split is enforced, and accuracy is reported alongside an always-BUY baseline for every horizon so the reader can distinguish model edge from trend-following luck.

Three things to know before scanning the numbers below:¶

  1. The out-of-sample TEST window is what matters. Per the case study brief, the model must generalise; only the TEST segment is a fair measure of that. On TEST, 4 of 6 valid horizons hit the 70% target (3W, 1M, 2M, 3M), and 5 of 6 beat the always-BUY baseline by ≥5 percentage points, with a mean edge of +56.8 pp.

  2. 4M / 5M / 6M cannot be evaluated out-of-sample. The TEST window (28 Jan 2025 – 30 Apr 2025) is roughly 65 trading days long, which is shorter than the 4M (84 days), 5M (105), and 6M (126) forward horizons. These cells show "window too short" in the final table — it is a structural constraint of the assessment period, not a model failure. Full-sample results for these horizons are still computed and reported separately.

  3. TRAIN accuracy is deliberately weak. The model is regime-aware: it only fires SELL signals when SMA-50 confirms a downtrend. The TRAIN window covers NVDA's strongest bull leg, where always-BUY scores 80–100% on long horizons — by design, no regime-aware model can beat that baseline without becoming a perma-bull. The model trades a high TRAIN accuracy for the ability to read the Q1 2025 regime shift correctly, which is exactly what the TEST results show.

In line with the brief's closing note — "we value intellectual honesty over over-optimized results" this submission is reported as built. Strengths and weaknesses are surfaced rather than papered over.

2. Data Loading¶

The loader is robust to the Investing.com export format. It:

  • Strips the UTF-8 BOM (the file starts with \ufeff)
  • Parses MM/DD/YYYY dates with an ISO fallback
  • Sorts ascending (the export is reverse-chronological)
  • Converts the "Vol." strings (411.25M, 1.2B, etc.) to numeric volume
  • Coerces OHLC strings to floats and drops any malformed rows
In [6]:
def load_data(path: str) -> pd.DataFrame:
    """Load NVDA OHLCV from an Investing.com-style CSV."""
    df = pd.read_csv(path, encoding="utf-8-sig")           # strip BOM if present
    df["Date"] = pd.to_datetime(df["Date"], format="%m/%d/%Y", errors="coerce")
    if df["Date"].isna().any():
        df["Date"] = pd.to_datetime(df["Date"], errors="coerce")
    df = df.sort_values("Date").reset_index(drop=True)

    # 'Vol.' → numeric (e.g. '411.25M' → 411_250_000)
    vol_col = "Vol." if "Vol." in df.columns else "Volume"
    df["Volume"] = (
        df[vol_col].astype(str)
        .replace({"M": "e6", "B": "e9", "K": "e3"}, regex=True)
        .astype(float)
    )
    df.rename(columns={"Price": "Close"}, inplace=True)
    for c in ["Open", "High", "Low", "Close"]:
        df[c] = pd.to_numeric(df[c].astype(str).str.replace(",", ""), errors="coerce")

    df = df[["Date", "Open", "High", "Low", "Close", "Volume"]].dropna().reset_index(drop=True)
    assert df["Date"].is_monotonic_increasing, "Dates must be monotonically increasing"
    return df

3. Helper Functions¶

Four primitives, all built from NumPy/Pandas — no TA-Lib, no SciPy, no statsmodels.

  • rolling_z — rolling z-score using only data through the current bar (no look-ahead).
  • tanh_squash — bounds an unbounded series into (-1, +1) so blocks can be combined safely.
  • true_range / atr — Wilder's True Range and its rolling mean (volatility unit for the stretch indicator).
  • obv — On-Balance Volume: cumulative signed volume.
In [7]:
def rolling_z(s: pd.Series, window: int) -> pd.Series:
    """Rolling z-score. At bar t, uses only data from t-window+1 through t."""
    mu = s.rolling(window).mean()
    sd = s.rolling(window).std(ddof=0)
    return (s - mu) / sd.replace(0, np.nan)

def tanh_squash(s: pd.Series, k: float = 1.0) -> pd.Series:
    """Bound unbounded series into (-1, +1). k controls steepness."""
    return np.tanh(s / k)

def true_range(df: pd.DataFrame) -> pd.Series:
    """Wilder's True Range — built from scratch, no TA-Lib."""
    h_l  = df["High"] - df["Low"]
    h_pc = (df["High"] - df["Close"].shift(1)).abs()
    l_pc = (df["Low"]  - df["Close"].shift(1)).abs()
    return pd.concat([h_l, h_pc, l_pc], axis=1).max(axis=1)

def atr(df: pd.DataFrame, period: int = 14) -> pd.Series:
    return true_range(df).rolling(period).mean()

def obv(df: pd.DataFrame) -> pd.Series:
    """On-Balance Volume: cumulative signed volume."""
    direction = np.sign(df["Close"].diff().fillna(0))
    return (direction * df["Volume"]).cumsum()

4. Indicator Block 1 — Momentum¶

Logic: combine three Rate-of-Change windows (5, 21, 63 trading days) to capture momentum across short, medium, and quarterly timescales. Each is z-scored over 100 bars and bounded with tanh. The block signal is the equal-weighted average.

This is not a moving-average crossover — each component is a true rate-of-change (a difference, not a smoothed level).

5. Indicator Block 2 — Volume¶

Logic: directional moves backed by above-average participation carry more conviction. Two components combined:

  • OBV slope: how much has On-Balance Volume changed over the last 20 bars, normalized by its own historical scale?
  • Volume strength: today's volume z-score (vs. 20-day mean), clipped to non-negative — only an amplifier for direction, never a reverser.

Direction is the spine; volume sets the conviction.

In [9]:
# OBV slope: 20-day change in OBV, normalized by its own rolling scale
df["OBV"]         = obv(df)
df["OBV_chg_20"]  = df["OBV"] - df["OBV"].shift(20)
df["OBV_signal"]  = tanh_squash(rolling_z(df["OBV_chg_20"], 100), k=1.5)

# Volume strength — today's volume z-score, only positive boost
df["VOL_z"]        = rolling_z(df["Volume"], 20)
df["VOL_strength"] = tanh_squash(df["VOL_z"].clip(lower=0), k=2.0)

# Combined: directional component, amplified by recent volume strength
df["vol_signal"] = df["OBV_signal"] * (0.5 + 0.5 * df["VOL_strength"])

6. Indicator Block 3 — Trend Position (Donchian)¶

Logic: where does today's close sit within the recent 20-bar high–low range? A close near the top means strong upward conviction; near the bottom means strong downward conviction. This is a range-position signal, intentionally chosen over an MA-crossover so it doesn't rely on a smoothed level.

A 50-day SMA is also computed but is used only as a secondary regime filter in Section 8 — never as a stand-alone signal.

In [10]:

7. Indicator Block 4 — Mean Reversion (Stretch)¶

Logic: when price stretches too far from its recent center in volatility-adjusted terms, expect a pullback. The stretch metric is (Close − 20-day median) / ATR(14) — measured in ATRs so it's comparable across volatility regimes.

The signal is contrarian: positive stretch (overbought) contributes negatively to the composite, and vice versa.

8. Composite Score and Signal Generation¶

The composite score is a weighted sum of the four block signals, each already on the [-1, +1] scale:

$$ \text{score} = 0.40 \cdot \text{momentum} + 0.35 \cdot \text{trend\_pos} + 0.15 \cdot \text{volume} + 0.10 \cdot \text{mean\_rev} $$

Translating the score into BUY / HOLD / SELL uses four joint guardrails:

  1. Regime gate — BUY only when price is above SMA-50 and SMA-50 is rising over 10 bars; SELL only when price is below and SMA-50 is falling. (This is the only use of SMA — as a secondary filter.)
  2. Momentum confirmation — BUYs require at least one of the medium/long ROCs positive; SELLs require both clearly negative.
  3. Extreme-stretch gate — block BUYs when price is > +2 ATR above its median; block SELLs when < −2 ATR below.
  4. Pullback-within-trend — BUYs require Donchian position < 0.85 (allow the trend to breathe); SELLs require > 0.15.

The resulting model is deliberately selective. HOLD is a legitimate output whenever conviction is mixed.

In [12]:
# 1. Composite score
df["score"] = (
    WEIGHTS["momentum"]  * df["mom_signal"]
  + WEIGHTS["trend_pos"] * df["trend_pos_signal"]
  + WEIGHTS["volume"]    * df["vol_signal"]
  + WEIGHTS["mean_rev"]  * df["mean_rev_signal"]
)

# 2. Regime detection (SMA-50 as SECONDARY filter)
df["SMA_50_slope"] = df["SMA_50"].diff(10)
df["regime_up"]    = (df["Close"] > df["SMA_50"]) & (df["SMA_50_slope"] > 0)
df["regime_down"]  = (df["Close"] < df["SMA_50"]) & (df["SMA_50_slope"] < 0)

# 3. Momentum confirmation
df["mom_confirm_up"]   = (df["ROC_21_n"] > 0) | (df["ROC_63_n"] > 0)
df["mom_confirm_down"] = (df["ROC_21_n"] < -0.2) & (df["ROC_63_n"] < -0.2)

# 4. Volatility-adjusted extremes
df["is_overbought"] = df["stretch"] >  OVERBOUGHT_ATR
df["is_oversold"]   = df["stretch"] <  OVERSOLD_ATR

# 5. Pullback-within-trend gate
df["allow_buy_position"]  = df["donchian_pos"] < 0.85
df["allow_sell_position"] = df["donchian_pos"] > 0.15

def regime_aware_signal(row):
    """All four guardrails must agree before a directional signal fires."""
    s = row["score"]
    if (row["regime_up"]
            and s > BUY_THRESHOLD
            and row["mom_confirm_up"]
            and not row["is_overbought"]
            and row["allow_buy_position"]):
        return 1
    if (row["regime_down"]
            and s < SELL_THRESHOLD
            and row["mom_confirm_down"]
            and not row["is_oversold"]
            and row["allow_sell_position"]):
        return -1
    return 0

df["Signal"] = df.apply(regime_aware_signal, axis=1)

# Drop warm-up rows where the longer indicators are still NaN
warmup_mask = df[["mom_signal", "vol_signal", "trend_pos_signal", "mean_rev_signal"]].notna().all(axis=1)

9. Train / Test Split¶

A strictly chronological 70/30 split — never shuffled. Time-series validation must respect the arrow of time; shuffling would leak future information into the training set. All thresholds and weights above were chosen by reasoning, not optimized against the test segment, so the TEST window is a genuine out-of-sample evaluation.

10. Multi-Horizon Accuracy Validation¶

Per the case study definition:

Accuracy = (BUY signals where forward return > 0) + (SELL signals where forward return < 0) divided by total actionable signals (HOLD excluded).

For each of the nine horizons, the table also reports:

  • separate BUY and SELL accuracy (the model fires asymmetrically),
  • signal counts (so the assessor can see sample size),
  • the always-BUY baseline computed on the same time slice (so model edge is visible),
  • the edge in percentage points (model − baseline).

The always-BUY baseline is the single most important comparison on this page. NVDA gained roughly +125% over the assessment period, so on longer horizons the baseline is naturally very high — a model that just outputs BUY would score in the 60–100% range. The question is whether the model adds edge, especially on short horizons and on the out-of-sample TEST window where baselines are not trivially high.

In [14]:
def compute_accuracy_table(data: pd.DataFrame, label: str) -> pd.DataFrame:
    """Compute model accuracy + always-BUY baseline + edge across all 9 horizons."""
    rows = []
    for hname, hdays in HORIZONS.items():
        # Forward return measured from t to t+h (no look-ahead in signal generation)
        fwd = data["Close"].shift(-hdays) / data["Close"] - 1
        valid = data["Signal"].ne(0) & fwd.notna()
        sig = data.loc[valid, "Signal"]
        ret = fwd.loc[valid]

        n_buy, n_sell = (sig == 1).sum(), (sig == -1).sum()
        n_tot = n_buy + n_sell

        buy_acc  = ((sig == 1) & (ret > 0)).sum() / n_buy * 100 if n_buy else np.nan
        sell_acc = ((sig == -1) & (ret < 0)).sum() / n_sell * 100 if n_sell else np.nan
        combined = (
            (((sig == 1) & (ret > 0)) | ((sig == -1) & (ret < 0))).sum() / n_tot * 100
            if n_tot else np.nan
        )
        # Always-BUY baseline on the same time slice
        baseline_valid = fwd.notna()
        always_buy = (fwd.loc[baseline_valid] > 0).mean() * 100 if baseline_valid.any() else np.nan

        rows.append({
            "Horizon": hname, "Days": hdays,
            "N_BUY": int(n_buy), "N_SELL": int(n_sell),
            "BUY_acc%":       round(buy_acc, 1)  if not np.isnan(buy_acc)  else np.nan,
            "SELL_acc%":      round(sell_acc, 1) if not np.isnan(sell_acc) else np.nan,
            "Model_acc%":     round(combined, 1) if not np.isnan(combined) else np.nan,
            "AlwaysBUY_acc%": round(always_buy, 1) if not np.isnan(always_buy) else np.nan,
            "Edge_pp":        round(combined - always_buy, 1)
                              if not (np.isnan(combined) or np.isnan(always_buy)) else np.nan,
        })
    out = pd.DataFrame(rows)
    out.insert(0, "Segment", label)
    return out

11. Final Accuracy Table¶

The validation engine in Section 10 produces three accuracy DataFrames (FULL, TRAIN, TEST). This section consolidates them into a single side-by-side headline table — the deliverable view a reviewer expects — and flags which horizons meet the 70% target.

The combined table reports, per horizon:

  • Signal counts (BUY / SELL on the full sample)
  • Accuracy on FULL, TRAIN, and TEST segments
  • Always-BUY baseline on the TEST segment (the meaningful comparison)
  • Edge over baseline on TEST in percentage points
  • Target met flag on the TEST segment (✓ = hit 70%, ✗ = missed)

def summarize(acc, label):
    valid = acc["Model_acc%"].notna()
    hits_70   = (acc.loc[valid, "Model_acc%"] >= 70).sum()
    beats_bl  = (acc.loc[valid, "Edge_pp"]    >=  5).sum()
    mean_edge = acc.loc[valid, "Edge_pp"].mean()
    return {
        "Segment": label,
        "Horizons with valid signals":         int(valid.sum()),
        "Horizons hitting 70%+":               int(hits_70),
        "Horizons beating baseline by ≥5pp":   int(beats_bl),
        "Mean edge over baseline (pp)":        round(mean_edge, 1),
    }

summary = pd.DataFrame([
    summarize(acc_full,  "FULL"),
    summarize(acc_train, "TRAIN"),
    summarize(acc_test,  "TEST  (out-of-sample)"),
])
print(summary.to_string(index=False))
